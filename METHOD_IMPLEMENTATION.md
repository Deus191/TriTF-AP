# TriTF-AP manuscript-to-code contract

This document identifies the code that implements each stated method component. It is an implementation trace, not evidence that the accuracy values currently written in the manuscript have been reproduced.

| Manuscript component | Public implementation | Enforced behavior |
|---|---|---|
| Three-channel input | `src/tf_preprocessing.py` | Exactly finite `(C3, Cz, C4)` input in shape `(3,T)` |
| Bipolar derivations | `paper_bipolar_pair` | Exactly `C3-Cz` and `C4-Cz`; there is no bypass switch |
| TF representation | `cwt_band`, `paper_tf_canvas`, `trial_tf_image` | Morlet CWT, 8--30 Hz, 64 frequency bins, two vertically concatenated log-power maps, joint per-trial maximum normalization, `jet`, `64x64x3` RGB |
| Dataset TF writing | `src/preWT.py` | Label-independent transform; labels only select output folders; writes `preprocessing.json` |
| IV-2b preprocessing | `src/preprocessing_2b.py` | A fixed four-second segment (seconds 4--8 relative to the stored trial marker; 1,000 samples at 250 Hz) is extracted; both T and E call the same paper TF writer |
| VAE augmentation | `src/augmentation.py` | VAE receives classifier fit indices only; one posterior sample per fit image; validation/test are not augmented |
| Classifier | `src/paper_model.py` | DW8/PW24, BN/ReLU, MP4/SDrop, four-branch RepDepthwise, PW32, BN/ReLU/SimAM, MP2/SDrop, GAP, Dense72, softmax |
| Deployment graph | `export_deploy` | Branch gates and BN are fused into one 3x3 depthwise path; stem/output BN are folded into pointwise convolutions |
| Training/evaluation | `src/Hope.py` | Adam 0.0003, batch 128, at most 200 epochs, `val_loss` early stopping with patience 10; final test is evaluated after checkpoint selection |
| Public image entry | `src/VAE.py` | Loads source and held-out images, then calls `Hope.Train` |
| OpenBMI LOSO entry | `src/train_openbmi.py` | Excludes the target subject from source data, then calls `Hope.Train` |

## Measured classifier size

For binary classification under TensorFlow 2.16.1:

- training graph: 4,526 parameters;
- fused deployment graph: 3,850 parameters.

The manuscript's “4.6K” is a rounded description and must state whether it refers to the training or deployment graph. The implementation does not add unused parameters to force a displayed count.

## Reproducibility boundary

The historical classifier was a different ordinary residual CNN, and historical TF images were generated by a different script. Consequently:

1. historical checkpoints are not compatible with this classifier;
2. historical images must not be mixed with images generated by `tritf_ap_paper_v1`;
3. manuscript accuracy, ablation, significance and visualization claims require fresh runs of this code and cannot be inferred from unit tests;
4. OpenBMI images supplied through a local configured path must be regenerated with the same representation contract—the filename alone does not prove provenance.

Regression tests verify the two exact derivations, two-map canvas, metadata, model layer contract, measured parameter counts, VAE split isolation and train/deploy numerical equivalence.
